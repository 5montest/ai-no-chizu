はじめての方へ

目的に合わせて学習を始める

全32章は、22章の基礎編（第1〜22章）と10章の実践編（第23〜32章）に分かれています。順番に読む必要はありません。下の学習ルートから目的の近いものを選ぶか、仕事で使う前の確認項目だけ先に読んでください。

仕事で使う前に確認しておくこと

  1. 会社で認められたサービスとアカウントを使い、入力してよい情報を確認する。
  2. 依頼には目的・読み手・材料・出力形式を書く。
  3. 返ってきた文章の事実、数字、出典を原資料で確かめる。
  4. 送信やデータ更新を任せるときは、権限・確認者・止める条件を決める。

目的別の学習ルートを選ぶ

5つのルートそれぞれに、最初に読むページと、読み終えたときにできることを書いています。各ページの冒頭にある「3行の要点」で説明の範囲を確かめ、必要な節を読んでください。読み進めながら別のルートへ移っても構いません。

01 AIの仕組みを学びたい方

AI・LLMの基本原理を順に学ぶ

AIという言葉が指す範囲から始め、入力が処理されて文章が返るまでの工程、TransformerのAttention、回答を作る2段階の計算を追います。

前提前提知識は不要です。第1章から順に読めます。

  1. AIはひとつの技術ではない7分

    AI・機械学習・LLMがそれぞれ何を指すかを分ける

  2. 文章が返るまでの全体工程9分

    入力が処理され、文章が返るまでの工程を追う

    先に読むと分かりやすい：機械学習は何を「学習」しているのか（機械学習が何を調整しているかが、この記事の前提になる）、文字列はトークンに分かれる（最初の工程に出てくるトークンの作り方）

  3. Attentionはどこを見ているのか9分

    Transformerが文中のどの語を参照しているかを読む

    先に読むと分かりやすい：Transformerは何を変えたのか（Attentionが組み込まれている全体像）

  4. 答える前の計算と、答えながらの計算10分

    回答を作る2段階の計算と、その費用の違いを押さえる

    先に読むと分かりやすい：知識を入れる段階と、応答を整える段階（学習の段階と、学習を終えたモデルを使う計算の違い）

読み終えたら：AI・機械学習・LLM・Transformerの関係と、回答が組み立てられる流れを説明できる。

02 生成AIを使い始めたい方

まず、一つの仕事で試す

依頼の書き方と、返ってきた内容の確かめ方を押さえます。

前提前提知識は不要です。生成AIのアカウントがあれば、本文の手順をそのまま試せます。

  1. 生成AIは地図のどこにいるのか8分

    生成AIができることと、保証しないことを知る

  2. 何をしてほしいかを、どう伝えるか9分

    目的・材料・形式をそろえて依頼する

  3. もっともらしい嘘はなぜ生まれるか9分

    自然な文章に含まれる誤りを見つける

  4. 入力と権限の両方を絞る10分

    入力する情報と、許す操作を確認する

読み終えたら：資料を渡して下書きを頼み、原文と照合して使える。

03 モデルや製品を選びたい方

モデルと製品を、同じ条件で比較する

モデルとアプリの区別から始め、製品の層、性能を測った条件、月額プランの枠までを並べて読みます。

前提前提知識は不要です。用語辞典を並べて読むと、用語の区別をその場で確認できます。

  1. モデルとサービスは別物である8分

    モデルと、アプリやサービスを区別する

  2. 製品は五つの層に分かれている11分

    製品をモデル・アプリ・提供元などの層に分けて見る

  3. ベンチマークは何を測っているのか10分

    性能の数字に付いている測定条件を読む

  4. 月額プランの枠を読む15分

    月額プランの利用上限と追加費用を確認する

読み終えたら：比較表の数値が、どのモデルをどの条件で測ったものかを質問できる。

04 社内導入を判断する方

効果・費用・運用を確かめる

対象の仕事を絞り、試験導入で何を測り、誰が運用するかを決めます。

前提社内の情報システム・セキュリティ担当との相談を前提にします。

  1. その仕事はAIに向いているか9分

    AIに任せる工程を決める

  2. 評価は用途ごとに作る11分

    実際の仕事で品質を測る

  3. コスト比較シートを作る14分

    利用量と確認作業を含めて費用を比べる

  4. 運用し続けるための設計6分

    更新・停止・問い合わせの担当を決める

読み終えたら：導入判断の確認シートに、条件・担当・未確認事項を残せる。

05 AIエージェントを開発したい方

CLIエージェントで実装し、変更を検証する

CLIコーディングエージェントを同じ題材で試し、モデルの外側の設計、サブエージェントへの分担、検査用のSkillの作り方を扱います。

前提ターミナルでコマンドを実行し、Gitで差分とコミットを確認できること。

  1. 三つのCLIを、同じ手順で試す15分

    三つのCLIを同じ手順で動かし、操作と出力を比べる

  2. モデルの外側を設計する9分

    モデルの外側で決める設定が、結果をどう変えるかを読む

  3. 調査・実装・レビューを、別の役に分ける17分

    調査・実装・レビューを役割ごとに分けて実行する

  4. 記事を検査するSkillを作る16分

    出力を検査するSkillを作り、確認を手順に組み込む

読み終えたら：エージェントに任せた変更を、差分とテストで自分で確認できる。

まずは、短い社内連絡の下書きで試す

以下は架空の例です。公開情報だけで試せるので、機密資料を用意する必要はありません。

目的：社内向けに、会議室の利用変更を知らせる。
読み手：同じ部署のメンバー。
材料：会議室Aは設備点検のため、11月2日の午前中は使えない。
形式：件名と、100字程度の本文。
条件：材料にない理由や、代わりの会議室を作らない。
分からない点は、確認事項として本文と分けて書く。

返答に「午後は必ず使える」「会議室Bへ移動してください」など、材料にない内容が加わっていないか確かめます。条件を書いても誤りは残りうるため、送る前の確認が必要です。

依頼の書き方を詳しく知るには、「何をしてほしいかを、どう伝えるか」へ。

迷ったときの調べ方

言葉の意味 → 用語辞典製品の違い → AI図鑑導入の確認 → 確認シート章の一覧 → 全32章

社内で使えるデータや契約の条件は、社内の情報システム・セキュリティ・法務などの担当窓口へ確認してください。
