第27章 CLIエージェント

三つのCLIを、同じ手順で試す

Claude Code、Codex CLI、OpenCode は、どれもターミナルで動くコーディングエージェントです。導入・サインイン・権限の確認を同じ順序で試し、何を許す道具なのかを自分の言葉で記録します。

仕組みや開発手順を詳しく扱うページです。業務で必要な範囲だけ先に読みたい場合は、学習ルートで別の入口を選べます。

3行の要点

  • Claude Code、Codex CLI、OpenCode は同じ層（ハーネス）の製品で、違いは配布元・必要なアカウント・権限の設計に出る。
  • 導入は公式ページのコマンドをそのまま写し、起動後にバージョンと作業ディレクトリを自分の目で確認する。
  • 最初のセッションでは書き換えをさせず、読み取りだけの依頼で「何を許可として求められるか」を観察して記録する。

前の章までで、製品を層に分けて見る方法と、モデルと料金の読み方を身につけました。ここからは手を動かします。題材は、ターミナルで動くコーディングエージェントです。Claude Code、Codex CLI、OpenCode の三つを、同じ順序で試します。

この記事に載せているコマンドと画面の説明は、2026-10-28 に各社の公式ドキュメントから写したものです。このサイトの作成環境では、三つとも実行していません。つまり未実機確認です。手順は公式の記載に沿っていますが、表示される文言や所要時間はあなたの環境と一致しないことがあります。違っていたら、公式ページの現在の記述を優先してください。

メモを取るときは、次の二つを混ぜないでください。

  • 公式記載（未実行）：公式ページの記述を写しただけの手順。この記事の手順はすべてこれです。
  • 実行確認済み：自分で通し、OS・バージョン・実行日・表示された結果を残した手順。

実行確認済みと書けるのは、実際に通したときだけです。通していない手順を「たぶん動く」で埋めると、あとで同じ環境を作り直せません。

三つとも「ハーネス」で、モデルではない

最初に層をそろえます。三つはどれもハーネスで、モデルそのものではありません。どのモデルを呼ぶかは、契約と設定で決まります。

Claude Code：Anthropic が配布するハーネスです。公式には、ターミナルでローカルに動き、バックエンドサーバーやリモートのコード索引を必要としないと書かれています。Mac、Linux、Windows に対応し、Claude の Pro / Max / Team / Enterprise プランか、Console のアカウントで使います。

Codex CLI：OpenAI が配布するハーネスです。ChatGPT でのサインイン、または API キーで使います。公式ドキュメントには macOS・Linux 向けのインストーラと、npm・Homebrew のタブが用意されています。

OpenCode：MIT ライセンスのオープンソースで、特定のモデル企業の製品ではありません。複数の提供元を切り替えて使う前提で作られています。ターミナルのほか、デスクトップアプリと IDE 拡張でも提供されています。

三つを比べるときに気をつけるのは、モデル名と混ぜないことです。「Codex CLI と Claude Opus 5.5 はどちらが賢いか」は、層が違うので問いとして成立しません。層の分け方は第23章の五層で扱いました。

用意するものは、ターミナルとアカウント一つ

始める前に、四つを用意します。特別なものは要りません。

  • ターミナル。macOS ならターミナル.app、Windows なら PowerShell か WSL。
  • 試してよいディレクトリ。既存の仕事のリポジトリは使いません。練習用に新しく作ります。
  • Git。変更を戻す手段として使います。
  • 使う製品のアカウント。三つとも、動かすには契約か API キーが要ります。

最初から三つ全部を入れる必要はありません。一つ入れて、権限の聞かれ方と読み取りの挙動を観察してから、次を入れるほうが判断が濁りません。メモリの少ない環境では、同時に動かさないほうが安全です。

金額はこの記事では扱いません。Claude のプラン料金は第25章で読み方を扱い、AI図鑑に確認日つきで記録しています。ChatGPT 側のプラン料金は、図鑑の確認時点で公式の料金ページを取得できなかったため（403）、額を書いていません。ここでも書きません。

導入は公式ページのコマンドを写す

インストール手順は更新されます。記事のコマンドをそのまま覚えるのではなく、公式ページを開いて、自分の OS のタブから写してください。写したら、取得日をメモに残します。

この節のコマンドは、複数の OS で実際に試したものではありません。OS によって表示や要る操作が変わる箇所は、公式ページのタブの記述を優先してください。

Claude Code：macOS・Linux・WSL のターミナルでは次の1行です。

curl -fsSL https://claude.ai/install.sh | bash

Windows の PowerShell では次のとおりです。

irm https://claude.ai/install.ps1 | iex

Homebrew を使っている場合は、cask でも入ります。

brew install --cask claude-code

入ったかどうかは、新しいターミナルを開いてバージョンを尋ねます。

claude --version

公式には、バージョン番号のあとに (Claude Code) が付くと書かれています。claude が見つからないと言われたら、インストール先が PATH に入っていません。公式のトラブルシュートに、PATH の直し方が載っています。

Codex CLI：macOS・Linux では、次の1行が案内されています。

curl -fsSL https://chatgpt.com/codex/install.sh | sh

npm と Homebrew のタブもありますが、この記事の確認時点では、タブの中のコマンド本文までは取得できていません。OS 別のタブを開いて、表示されているコマンドをそのまま使ってください。ここで推測したコマンドを書くことはしません。

OpenCode：インストールスクリプトか、パッケージマネージャで入ります。

curl -fsSL https://opencode.ai/install | bash

npm を使う場合は次のとおりです。

npm install -g opencode-ai

Homebrew なら brew install anomalyco/tap/opencode です。Windows では Chocolatey、Scoop、npm が案内されていますが、公式は WSL の利用を勧めています。

起動して、最初の許可を読む

三つとも、起動の前にプロジェクトのディレクトリへ移動します。ここが作業範囲になります。移動を間違えると、関係のないファイルを読ませることになります。

cd /path/to/your/project

Claude Code は claude で起動します。初回はブラウザでのサインインを求められます。プロンプトには、バージョン、使っているモデル、作業ディレクトリが表示されます。/help でコマンド一覧、Shift+Tab で権限モードの切り替えです。何が許可なしで実行できるかは、この権限モードで変わります。

Codex CLI は codex で起動し、初回は「Sign in with ChatGPT」などの方法を選びます。セッションの中で /permissions を実行すると、何を許可するかを選べます。公式の説明では、ファイルの編集やコマンドの実行を確認なしで許す範囲と、いま有効なサンドボックス・書き込み可能なディレクトリを確認できます。/model でモデルと推論の強さ、/status で作業ディレクトリを確認できます。

OpenCode は opencode で起動し、/connect から提供元を選びます。OpenCode 自身の提供元を使う場合は、案内された先でサインインし、請求情報を登録して API キーを発行し、プロンプトに貼ります。Tab キーで Plan mode に入り、変更を行わない状態で方針だけを出させられます。

Codex CLI のサンドボックスは、名前だけ覚えても判断できません。何ができて何ができないかの対応は次のとおりです。

モードできること注意
read-onlyファイルを読み、読み取り専用のサンドボックス内でコマンドを動かす外に出る操作は承認が要る
workspace-writeワークスペース内の読み書きとコマンド実行ネットワークは既定で無効。外側の編集や通信は承認が要る
danger-full-accessサンドボックスも承認も無いリスクが高いとして推奨されていない

起動時の既定は、バージョン管理されたフォルダなら Auto、そうでなければ read-only と案内されています。作業ディレクトリを信頼するまでは read-only で始まることもあります。Auto は --sandbox workspace-write --ask-for-approval on-request と同じ意味だと書かれています。確認したいときは、起動時にモードを明示できます。

codex --sandbox read-only --ask-for-approval on-request
試す人向け演習・記入例と確認の観点

演習：空のリポジトリで、読むだけを頼む

ここからが本題です。目的は、便利さを体感することではありません。何を許可として求められ、どこまで勝手に動くのかを、自分の環境で確かめることです。

  1. 練習用のディレクトリを作り、Git で初期化します。
mkdir ~/cli-practice
cd ~/cli-practice
git init
  1. 読ませるファイルを一つ、手で置きます。エージェントに作らせません。最初の状態を自分で決めるためです。
printf '# 練習用\n\nこのリポジトリはCLIエージェントの練習にだけ使う。\n' > README.md
git add README.md
git commit -m "最初のファイル"
  1. エージェントを起動し、読むだけの依頼をします。依頼文は、次のように書きます。
このディレクトリにあるファイルを読んで、何のためのリポジトリかを1段落で説明してください。ファイルは変更しないでください。

  1. 許可を求められたら、内容を読んでから答えます。読むだけの依頼なのに書き込みの許可を求められたら、いったん断り、なぜ必要かを聞きます。断って困ることは、この練習ではありません。

  2. 変更を伴う道具を使う場合は、Plan mode で同じ依頼をしてみます。OpenCode なら Tab キーです。方針だけが出て、ファイルが変わらないことを確かめます。

  3. 終了して、状態を確認します。

git status

期待する結果は、変更が何も無い状態です。Git の言語設定によって文言は変わりますが、working tree clean に相当する表示が出ます。差分がゼロで、許可のやり取りがメモに残っていれば、この演習は成功です。

うまくいかないときは、次の順で切り分けます。コマンドが見つからない場合は、新しいターミナルを開いて PATH を反映させます。サインインが終わらない場合は、ブラウザの別タブやプロキシの設定を疑い、公式のトラブルシュートを読みます。npm install のような通信を伴う操作を頼んで拒否された場合は、サンドボックスのネットワークが既定で無効なためです。これは不具合ではなく、既定の設計です。何をしているか分からない許可が出たら、断って構いません。分からないまま許す習慣のほうが、あとで困ります。

記録すると、選ぶ基準が変わる

三つを触ったら、一枚の表にまとめます。ここで埋まらない欄は、空にせず「未確認」と書きます。

項目記録すること
導入写したコマンド、OS とバージョン、取得日、実行結果（通ったか、出た文言）
必要なアカウントプラン名や API キーの有無
起動コマンドと、最初に出た画面
作業範囲どこを読めるか、どこに書けるか
変更前の許可求められたか、何を許したか
読み取り専用の指定方法と、指定したときの挙動
ネットワーク既定で通信できるか
気になった点用語の分かりにくさ、待ち時間、表示

この表は、製品の優劣を付けるためのものではありません。自分が何を許して使うのかを、使う前に言葉にしておくためのものです。

評価

次の四つで点検します。第一に、三つ（または一つ）について上の表が埋まっているか。第二に、許可について「何回聞かれたか」ではなく「何を許したか」を書けているか。第三に、公式に確認できなかった欄に「未確認」と書いたか。空欄や「たぶん」は、あとで判断を誤らせます。第四に、練習用リポジトリが clean かどうかです。

書き直しが要るのは、次の状態です。許可の内容を覚えていない。どのディレクトリで動かしたか分からない。インストールした日を書いていない。どれも、あとで同じ環境を再現できない印です。

できあがるもの

手元に残るのは、比較メモ一枚と、変更の無い練習用リポジトリです。メモは、次の章でそのまま使います。

次の記事では、同じリポジトリで小さな変更を一つだけ入れ、テストと差分で検収し、必要なら戻します。変更を自分で検収するへ進んでください。

製品ごとの記録は、AI図鑑の個別ページにも確認日つきで残しています。Claude Code、Codex CLI、OpenCodeの3件は比較ページで並べることもできます。図鑑の値と自分のメモが食い違ったら、確認日を比べて、新しいほうを採ってください。
