第23章 製品の全体像

製品は五つの層に分かれている

ChatGPT、Claude、Codex、Claude Code は同じ種類の製品ではありません。モデル・ハーネス・利用アプリ・拡張機構・契約の五つに分けると、自分が何を選んでいるのかが見えます。

3行の要点

  • AI製品は、モデル・ハーネス・利用アプリ・拡張機構・契約の五つの層に分けて読むと、比べる相手を取り違えずに済む。
  • 同じブランドが複数の層を持つため、「Claude は賢いか」のような問いは、層を決めないと答えられない。
  • 用途・OS・予算・機密性の四条件で絞り、いま使っている製品を層に置くと、自分の選択がどこで決まっているかが見える。

「ChatGPT」「Claude」「Codex」「Claude Code」。この四つは、よく同じ「AI」という一言でまとめられます。しかし四つを横に並べて「どれが優れているか」と考えても、判断はほとんど進みません。四つは同じ種類の製品ではないからです。どれも、計算する本体と、それを動かす外側の仕組みと、人が触る画面と、支払いの条件という、別々の層の組み合わせでできています。層が違えば、比べるべき項目も変わります。

この記事の目的は、製品名を覚えることではありません。名前を見たときに「これはどの層の話か」と切り分けられるようになることです。第12章で扱ったハーネスの考え方を、実際の製品名に当てはめていきます。

五つの層に分ける

まず製品を五つの層に分けます。この分け方はこのサイトの整理であって、業界の標準用語ではありません。ただ、料金表や発表資料を読むときの足場としては、この五つで足ります。

層何を決めるか例
モデル入力から出力を計算する本体。知識と判断の上限を決めるClaude Opus 5.5、GPT-6 Astra
ハーネスモデルに道具を使わせ、手順を回し、権限と予算を守る外側の仕組みClaude Code、Codex CLI、OpenCode
利用アプリ人が指示を出し、結果を読む画面Claude のアプリ、ChatGPT
拡張機構ハーネスに後から足す部品Skills、Plugins、MCP、Hooks
契約・プラン使える量、使えるモデル、支払い方の条件Free、Pro、Max、Team など

モデル：入力のトークン列を受け取り、次に来るトークンの確率を出す本体。第2部でたどった計算そのもので、文脈長のような仕様もここに属します。

ハーネス：モデルの外側で、計画を立て、道具を呼び、結果を確かめ、失敗したらやり直す仕組み。ファイルを読む、コマンドを実行する、テストを走らせるといった動作は、モデルではなくハーネスと実行環境の仕事です。

利用アプリ：人が触る部分。同じモデルでも、アプリが違えば指示の出し方も履歴の持ち方も変わります。

拡張機構：ハーネスに追加する部品。Function Calling を土台にした道具の追加や、作業手順をまとめた Skill、外部サービスにつなぐ MCP などがここに入ります。図鑑では独立した分類にせず、ハーネスの能力（Skills、Plugins、MCP、サブエージェント、Plan Mode、権限）として記録しています。単体で動く製品ではなく、必ず何かのハーネスの上で動くものだからです。

契約：どのモデルを、どれだけ使えるかの条件。月額、利用枠、モデル別の倍率がここに入ります。詳しくは月額プランの枠を読むで扱います。

五つの層は、上から順に「賢さ」を決めるわけではありません。モデルが賢くても、ハーネスが道具を渡さなければファイルは読めません。ハーネスが良くても、契約の枠が尽きれば作業は止まります。層ごとに、できることと、止まる理由が違います。

使う場所を先に決める

層を分けたら、次は入り口です。同じモデルでも、どこから使うかで作業の進め方が変わります。図鑑ではこの入り口を「使う場所」として記録しています。

使う場所何をする形か向く作業
Webブラウザ画面に文章を打ち、返答を読む下調べ、文章の推敲、単発の質問
デスクトップアプリ手元のアプリとして起動する常用する作業、画面を並べた作業
モバイルアプリ端末から短く指示する移動中の確認、写真や音声の入力
CLI端末で文字のコマンドとして呼ぶリポジトリ内の作業、繰り返しの自動化
IDE拡張エディタの中で呼ぶコードを書きながらの相談
API自分のプログラムから呼ぶ業務システムへの組み込み、大量処理
ローカル実行手元の機材でモデルの計算を回す外部に出せないデータの処理

CLI と API は混同されやすいのですが、別の層です。CLI はハーネスの一種で、人が端末から使うための入り口です。API はモデルを呼ぶための接口で、そこにハーネスは付いてきません。API を直接呼ぶと、道具の呼び出しも、やり直しの制御も、自分で書くことになります。

ローカル実行は、計算を手元の機材に移す形です。費用は電気代と機材に移り、データは外に出ません。その代わり、動かせるモデルの大きさは手元のメモリと GPU に縛られます。

同じブランドが複数の層を持つ

層の分け方が効くのは、一つのブランドが複数の層にまたがっているときです。

Anthropic は、モデルとして Claude Fable 5.1、Claude Opus 5.5、Claude Sonnet 5.5、Claude Haiku 5.5 を持っています。ハーネスとしては Claude Code、利用アプリとしては Claude のアプリ、契約としては Free、Pro、Max、Team、Enterprise を持っています。だから「Claude は速いか」という問いは、モデルの応答速度の話なのか、アプリの体感の話なのか、契約の枠に当たった話なのかを決めないと答えられません。

OpenAI も同じ形です。モデルに GPT-6 Astra、GPT-6.1 Sol、GPT-6.1 Terra、GPT-6 Luna があり、ハーネスに Codex CLI、利用アプリに ChatGPT、契約に各プランがあります。

混ざりやすいのは、ハーネスの名前とモデルの名前です。「Claude Code の調子が悪い」と言うとき、原因はモデルの応答かもしれませんし、ハーネスの手順かもしれませんし、契約の枠かもしれません。三つを分けて言えると、相談の精度が上がります。同じモデルを別のハーネスで使って結果が変われば、それはハーネスの差です。モデルを替えて結果が変われば、それはモデルの差です。両方を同時に替えると、どちらの効果か分からなくなります。

よくある誤解

「上位のプランにすれば、モデルそのものが賢くなる」と読むのは誤りです。プランが変えるのは、使えるモデルの範囲と使える量です。同じモデルなら応答の質は同じで、違うのは枠と待ち時間になります。

四つの条件で絞る

層と入り口が分かったら、自分の条件で絞ります。実際に効くのは、次の四つです。

用途は、何をさせるかです。文章を書くのか、コードを直すのか、大量の分類をするのか、音声を文字にするのかで、必要なモデルの種類が変わります。

OS と機材は、どこで動かせるかを決めます。デスクトップアプリは対応する OS が限られます。ローカル実行は、手元のメモリと GPU の容量が上限になります。

予算は、月額と従量のどちらで払うかを含みます。月額は使わなくても固定、従量は使った分だけ増えます。同じ予算でも、使い方によって得な形が変わります。

機密性は、データを外に出せるかを決めます。外部に出せないなら、ローカル実行か、契約上の条件を満たす経路に限られます。

この四つは、たいてい一つか二つ決まれば残りが絞れます。「社外秘の文書を扱う」「手元は Windows」「月の予算は決まっている」の三つが決まれば、候補はかなり小さくなります。

いま使っている製品を層に置いてみる

ここまでの整理を、手元の製品で確かめます。新しいサービスに登録する必要はありません。いま使っているもの、使おうか迷っているものを紙に置くだけです。

  1. 最近1週間で使った AI の名前を、思いつく限り書き出します。製品名でもモデル名でも構いません。
  2. それぞれの名前の横に、モデル・ハーネス・利用アプリ・拡張機構・契約のどれかを書きます。分からなければ「分からない」と書きます。
  3. 「分からない」が残ったものについて、その製品の公式ページで、どのモデルが動いているか、どんな入り口があるかを確認します。
  4. 書き出した名前を、使う場所（Web、デスクトップ、モバイル、CLI、IDE、API、ローカル）で並べ直します。
  5. 用途・OS・予算・機密性の四条件のうち、自分の場合に決まっているものを書き添えます。

期待する結果は、名前の数より「層が分かれた数」です。10個の名前が、モデル4つ・ハーネス2つ・アプリ2つ・契約2つに整理できれば、その人の見取り図はできています。逆に、全部が「アプリ」に見えるなら、モデル名と製品名がまだ混ざっています。

うまくいかないときの典型的な詰まりは三つあります。一つ目は、モデル名が分からない製品です。その場合は「モデル未確認」と書いて空欄にし、推測で埋めません。二つ目は、同じ名前が複数の層に見える場合です。たとえば「Claude」はモデル系列の名前でもあり、アプリの名前でもあります。そのときは層ごとに行を分けます。三つ目は、社内で独自に呼ばれている略称です。略称は正式名の横に括弧で添え、正式名が分からなければ「未確認」と書きます。

この作業で使う情報は、各社の公式ページだけにします。比較記事やまとめサイトの製品名は、公式で確認できるまで「再販情報のみ」として扱い、自分の見取り図の確定情報にはしません。

できあがるもの

この実習の成果物は、次の4列を持つ一枚の表です。用紙でも表計算でも構いません。

名前層使う場所確認したこと・未確認のこと
Claude Opus 5.5モデルAPI単価と文脈長は公式で確認（2026-10-28）
Claude CodeハーネスCLI、IDE拡張どのモデルを使うかは設定次第（未確認）
Claude Pro契約Web、デスクトップ、モバイル5時間枠と週間枠がある（2026-10-28）

最後の列が、この表の本体です。確認したことと未確認のことを分けておくと、次に何を調べるかが決まります。確認日も一緒に書いてください。料金と枠は数か月で変わるので、日付のない表は後で使えません。

同じやり方で、迷っている製品を2つか3つ足すと、選択の材料になります。ただし層の違うものを同じ列で点数づけしないでください。モデルとプランを並べて「どちらが優れているか」は決められません。

評価

自分の見取り図が正しいかは、次の三つで確かめられます。第一に、層の違う二つの名前を「優劣」で語っていないこと。第二に、未確認の欄が残っていること。全部が埋まっている表は、たいてい推測で埋まっています。第三に、確認日が入っていることです。

逆に、次の状態なら書き直しが必要です。「モデル」の欄にハーネスの名前が入っている。「契約」の欄にモデル名が入っている。確認日が全部同じで、しかも今日の日付になっている。どれも、層と事実が混ざった印です。

次は、この五つの層を一枚のシートに落とし、自分の用途に合う製品を選ぶ手順に進みます。製品選択シートを作るへ進みましょう。
