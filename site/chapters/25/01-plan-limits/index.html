第25章 料金とコスパ

月額プランの枠を読む

月額・クレジット・利用枠・単価は別の項目です。5時間枠と週間枠、モデル別の倍率、入力と出力の別建て、税と地域差を分けて読むと、実効コストが見えます。

3行の要点

  • 月額・クレジット・利用枠・トークン単価は別の項目で、一つにまとめると実効コストを読み違える。
  • 月額プランの枠は時間窓で数え、モデルごとの倍率がかかるため、リクエスト回数だけでは消費量を測れない。
  • API の単価は入力と出力が別建てで、文脈の長さ・キャッシュ・バッチ・税・地域で条件が変わる。

料金の話は、金額そのものより読み方でつまずきます。「月 20 ドルのプランと、100万トークン 2 ドルのAPI、どちらが安いか」という問いに答えられる人は多くありません。答えられないのは、計算が苦手だからではなく、比べる単位が違うからです。

この記事では、金額を暗記するのではなく、料金表のどこを読めば実効コストが見えるかを扱います。金額はすべて 2026-10-28 に公式ページで確認したもので、通貨は米ドル、特に断りのない限り税別です。値は変わりますから、使う前に必ず公式ページで取り直してください。

四つの支払い方を分ける

料金の話には、少なくとも四つの別項目があります。これを混ぜると、表の数字が読めなくなります。

項目何を表すかどこで効くか
月額使わなくても発生する固定費予算の下限を決める
クレジット前払い、または枠を超えた分の支払い上限を超えたときの逃げ道
利用枠一定時間に使える量の上限作業が途中で止まる原因
トークン単価使った量に比例する従量の費用大量処理の費用を決める

クレジット：あらかじめ購入した利用量。月額プランの枠を使い切ったあとに、API 単価で続きを払う形で使われることが多い。

この四つは、同じ契約の中に同時に存在します。月額プランにも利用枠があり、枠を超えるとクレジットで払い、クレジットも尽きれば止まる。だから「月 20 ドルで使い放題」という理解は、たいていどこかで崩れます。

月額プランの枠を読む

まず月額プランです。Anthropic の料金ページを例に取ります。2026-10-28 に確認した内容は次のとおりです。

プラン月額使えるモデルの範囲枠の特徴
Free$0Sonnet と Haiku枠が小さい
Pro$20（年払い $200）Opus・Sonnet・Haiku。Fable はクレジット経由Free の5倍以上、5時間枠と週間枠
Max$100 から上位モデルを含むPro の5倍または20倍。月払いのみ
Team Standard$25 / 席 / 月（年払い $20）2〜150 席API クレジットを月 $500 まで共有
Team Premium$125 / 席 / 月（年払い $100）Standard の5倍—
Enterprise$20 / 席 / 月（年払い）、20 席から席料に加えて API 単価で利用個別の契約

ここで読み取るべき点は三つあります。第一に、枠は「5時間」という窓で区切られ、さらに週間の枠が重なります。1か月の総量ではなく、短い窓での回復を前提にした設計です。第二に、枠は Web・デスクトップ・モバイル・Claude Code で共有されます。複数の入り口を同時に使うと、同じ枠を奪い合います。第三に、上位モデルほど同じ作業で枠を多く消費します。モデル別の倍率がかかるためです。

よくある誤解

「Max にすれば使い放題」という理解は誤りです。Max は上位モデルの利用と枠の拡大を含みますが、枠そのものは残ります。月額だけでなく、枠の窓と倍率まで読んでください。

料金ページには、Max の月額が「$100 から」と下限で書かれています。上限の額は確認できていません。下限だけを見て「月 100 ドル」と決めつけず、契約前に上限を確かめてください。

このサイトの図鑑では、Claude Team の席単価をまだ「未確認」として記録しています。公式ページには上の表の額が載っていますから、図鑑の側の記録が追いついていない状態です。確認待ちの項目として扱い、記事の数字を優先してください。

モデル別の月次枠という形

月額プランの中には、モデルごとに別々の枠を持つ形もあります。OpenCode Go がその例です。

Go は月 $10、Go Plus は月 $40 です。ここで誤解しやすいのが、枠の持ち方です。Go は一つの共通クレジットではなく、モデルごとに月次の金額枠を持ちます。たとえば GLM-5.3 は $15 と $120、DeepSeek V4.1 Flash は $80 と $160 のように、モデルごとに二つの額が示されています。安いほうが Go、高いほうが Go Plus の枠です。

さらに、それぞれの枠は三つの窓に分かれます。5時間で枠の 20 パーセント、週間で 50 パーセント、月間で 100 パーセントという配分で、余りは翌期間に繰り越されません。つまり月末に枠が余っていても、翌月に足されることはありません。

同じページには、混雑時間の倍率も書かれています。DeepSeek はピーク時に通常の2倍の消費になり、ピークは UTC の 01:00〜04:00 と 06:00〜10:00 の平日です。日本時間では昼前と夕方にあたります。同じ作業でも時間帯で費用が変わるわけです。

リクエスト回数は、このページでも推定値として示されています。回数は文脈の長さで変わるため、確定的な数字にはなりません。

API 単価の読み方

次に、従量課金の単価です。ここには六つの条件がかかります。

第一に、入力と出力が別建てです。100万トークンあたりの単価が、入力と出力で違います。主要な提供元では出力のほうが高く、たとえば OpenAI の GPT-6.1 Sol は入力 $2.00、出力 $10.00 です。合計は入力分と出力分を別々に計算して足します。

第二に、単価の段階です。同じモデルでも条件で単価が変わります。Anthropic の Claude Haiku 5.5 は、10万トークンまでが入力 $0.10・出力 $0.50、それを超えると入力 $0.50・出力 $2.50 になります。OpenAI は 272K トークンを境に、短い場合と長い場合で単価が切り替わります。GPT-6 Astra は短い場合が $10.00・$50.00、長い場合が $20.00・$75.00 です。

第三に、キャッシュです。同じ前置きを繰り返し送る場合、キャッシュとして保存した部分の読み書きには別の単価が設定されます。OpenAI はキャッシュの書き込みを通常単価の 1.25 倍（30分保持）または 2.5 倍（12時間保持）とし、読み出しは割安な単価を設定しています。額は料金表の該当行を見てください。同じ前置きを何度も送る使い方では、この差が大きく効きます。

第四に、バッチです。急がない処理をまとめて流すと、両社とも通常の 50 パーセントの単価になります。夜間に流してよい処理なら、これが最も効く割引です。

第五に、速度の区分です。OpenAI には Fast と Ultrafast という区分があり、Fast は単価が2倍、Ultrafast は対応するモデルが限られます（GPT-6 Astra と GPT-6.1 Sol のみ）。待ち時間を金で買う形です。

第六に、税と地域です。Anthropic の API 単価は税別で示されています。OpenAI は 2026-03-05 以降に公開されたモデルについて、地域指定や FedRAMP の利用で 10 パーセント増しになります。Anthropic にも米国内のみで推論する指定があり、その場合は 1.1 倍です。

税別：表示額に消費税や付加価値税が含まれていないこと。日本の利用者なら、実際の支払額は表示より大きくなります。

定額と従量をそのまま換算できない理由

ここまで読むと、月額プランとAPIのどちらが得かを計算したくなります。しかし、そのままでは換算できません。理由は三つあります。

一つ目は、枠が時間窓で数えられることです。月額プランの枠は5時間ごとに回復するので、1か月の総量は使い方の分布で変わります。月初に集中して使う人と、毎日少しずつ使う人では、同じ枠でも使える総量が違います。

二つ目は、モデル別の倍率です。同じ1回のやり取りでも、重いモデルなら枠を多く消費します。API の単価がモデルごとに違うのと同じことが、枠でも起きます。

三つ目は、無料枠と追加課金の境目が読めないことです。枠を超えたときに止まるのか、クレジットで続くのか、契約によって違います。止まると読んでいたら課金されていた、という食い違いはここで起きます。

ですから換算するときは、前提を三つ書きます。1か月に何回使うか、そのうち何割が重いモデルか、枠を超えたときにどうするか。この三つを書かずに出した結論は、条件が変わると使えません。

試す人向け演習・記入例と確認の観点

演習：自分の1か月を書き出す

契約を変えずに、いまの使い方を数字にします。新しい支払いは発生しません。

  1. 直近1週間で、AI を使った回数と、そのうち長い文章を扱った回数を書きます。
  2. 使ったモデルの名前を書きます。分からなければ「不明」と書きます。
  3. 1回あたりの入力の長さを、おおよその文字数で書きます。会話の履歴が含まれることを忘れないでください。
  4. 同じ前置きを毎回送っているかどうかを書きます。送っているなら、キャッシュの対象になります。
  5. 急がない処理が何割あるかを書きます。バッチの対象になります。
  6. いまの契約で、枠に当たって止まったことがあるかを書きます。

期待する結果は、「1か月に何回・うち長文が何回・急がない処理が何割」の三つが埋まることです。この三つが無いと、どの料金表も読めません。

うまくいかないときは、次のどれかです。回数が数えられない場合は、履歴の画面で日付ごとに数えます。入力量が分からない場合は、文字数を4で割った数を目安にします。日本語では1文字がおよそ1トークン前後になるためです。厳密な値ではありませんが、桁を見るには足ります。モデル名が分からない場合は、契約の画面に表示されているはずです。それでも分からなければ「不明」のまま残します。

できあがるもの

成果物は、次の列を持つ料金条件メモです。

項目自分の場合根拠
いまの契約月額プラン、月 $20（税別）公式ページ（2026-10-28）
1か月の利用回数約 120 回履歴から集計
うち長文約 30 回履歴から集計
枠に当たった回数2 回自分の記録
急がない処理の割合4 割自分の記録
未確認のこと枠を超えたときの課金の有無契約画面で確認する

最後の行が、このメモの目的です。金額の比較より、何が分かっていないかを残すほうが役に立ちます。

評価

メモは、次の三つで点検します。第一に、月額・枠・単価を別の行に分けているか。第二に、各金額に通貨・税の扱い・確認日が付いているか。第三に、未確認の行が残っているかです。

逆に、次の状態なら書き直しが必要です。金額だけが並んでいて、条件が書かれていない。「使い放題」と書いてある。確認日が入っていない。どれも、数字だけを写して条件を落とした印です。

次は、このメモを使って実際に試算します。前提の置き方と、比べてよい組み合わせの作り方を、コスト比較シートを作るで扱います。
