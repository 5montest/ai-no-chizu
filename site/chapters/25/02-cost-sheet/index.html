第25章 料金とコスパ

コスト比較シートを作る

回数・入力・出力の三つを決めれば、トークン単価から試算できます。段階・割引・税を反映し、月額プランとは列を分けて、第三者が同じ数を入れれば同じ答えになるシートを作ります。

3行の要点

  • 試算は「1か月の回数・1回の入力・1回の出力」の三つを決めれば始められ、入力と出力を別々に掛けて足す。
  • 段階単価・バッチ・キャッシュ・税は、条件を確認できたときだけ反映し、確認できない条件は試算に混ぜずに注記として残す。
  • 月額プランと従量課金は同じ列に入れず、金額・通貨・税・確認日・前提を揃えた列で並べる。

前の記事で、自分の1か月の使い方を数字にしました。この記事では、その数字を金額に変えます。目標は精密な見積もりではありません。第三者が同じ数を入れたら同じ答えになる、説明可能な試算です。

試算が信用されないのは、たいてい前提が書かれていないからです。「月 2 ドルくらい」と言われても、何回使って、どれくらいの長さで、どのモデルかが分からなければ、確かめようがありません。逆に前提が書いてあれば、条件が変わったときにどこを直せばよいかも分かります。

金額は 2026-10-28 に公式ページで確認した米ドル建ての税別単価です。為替と税は含めていません。

三つの数を先に決める

試算に必要なのは、次の三つです。

  • 1か月の利用回数
  • 1回あたりの入力トークン数
  • 1回あたりの出力トークン数

入力と出力を分けるのは、単価が違うからです。主要な提供元では、出力の単価が入力の5倍前後に設定されています。まとめて数えると、出力の重みが消えてしまいます。

入力トークン：モデルに渡す側の量。指示文、会話の履歴、貼り付けた資料がすべて含まれます。履歴が積み上がる使い方では、回数を重ねるほど1回あたりの入力が増えます。

出力トークン：モデルが返す側の量。長い下書きを書かせると、ここが膨らみます。

入力の見積もりで最も間違えやすいのは、会話の履歴を数え忘れることです。10回やり取りした会話の11回目は、それまでの10回分がすべて入力に入ります。1回あたりの入力を「今回打った文の長さ」で見積もると、実際の半分以下になります。

日本語の文字数からトークン数への換算は、およそ1文字1トークンと考えてください。正確な値はモデルと文字の種類で変わりますが、桁を見るには足ります。英語が混ざるとトークン数は減ります。

単価を掛けて足す

計算は単純です。入力の量に入力単価を掛け、出力の量に出力単価を掛けて、足します。単価は100万トークンあたりで示されているので、トークン数を100万で割ってから掛けます。

例として、1か月に120回、1回あたり入力4,000トークン・出力800トークンの使い方を試算します。合計は入力48万トークン、出力9.6万トークンです。

モデル入力単価出力単価入力の費用出力の費用合計
Claude Sonnet 5.5$2.00$10.00$0.96$0.96$1.92
GPT-6.1 Terra$1.00$5.00$0.48$0.48$0.96
GPT-6 Luna$0.10$0.50$0.048$0.048$0.096

この表から読み取れることが二つあります。第一に、同じ使い方でもモデルによって20倍の差が出ます。第二に、Sonnet 5.5 では入力と出力の費用がほぼ同じです。入力4,000に対して出力800しかないのに、単価が5倍なので釣り合っています。

つまり、費用を下げたいときに効くのは、出力を短くすることです。出力を800から400に減らせば、Sonnet 5.5 の出力の費用は $0.96 から $0.48 に下がり、合計は $1.44 になります。「短く答えて」と指示するだけで半分になる場面は珍しくありません。

段階と割引を反映する

上の計算は基本単価だけです。実際には四つの条件が加わります。ただし、確認できた条件だけを反映してください。

第一に、文脈長による段階です。Anthropic の Claude Haiku 5.5 は、10万トークンまでと、それを超える場合で単価が変わります。OpenAI は272Kトークンを境に切り替わります。ここで注意が必要なのは、段階が「1リクエストあたりの入力の長さ」で決まることです。1回の入力が4,000トークンなら、1か月の合計が48万トークンでも安いほうの段階が適用されます。合計額で段階を判断すると間違えます。

第二に、バッチです。急がない処理をまとめて流すと、両社とも単価が50パーセントになります。上の表で4割が急がない処理なら、その分だけ半額になります。

第三に、キャッシュです。同じ前置きを毎回送っている場合、その部分はキャッシュの対象になります。ただし、キャッシュの読み書きの単価は通常の単価と別に設定されており、額は条件ごとに違います。この記事では額を出しません。公式ページの該当行を確認し、確認できた場合だけ試算に反映してください。確認できなかった場合は、キャッシュを使わない前提で計算し、その前提を注記に残します。

第四に、税と地域です。ここまでの金額はすべて税別です。日本の利用者なら、実際の支払額は消費税の分だけ増えます。また、米国内のみで推論する指定には 1.1 倍、OpenAI の一部のモデルでは地域指定や FedRAMP の利用で 10 パーセント増しといった条件があります。使う予定があるなら、その倍率を掛けた行を別に作ってください。

反映しなかった条件は、消さずに注記に書きます。「バッチ割引は未適用」「キャッシュは使わない前提」「税別」の三行があれば、この試算の限界が読む人に伝わります。

月額プランとは列を分ける

試算が出ると、月額プランと比べたくなります。ここで表を一つにしてはいけません。

理由は単位です。月額プランは月あたりの固定額で、使える量は「5時間枠」のような時間窓とモデル別の倍率で決まります。これは金額に換算できません。提供元が枠の金額を公開していないからです。

ですから表は二つに分けます。左が従量課金の試算、右が月額プランの条件です。右側には、金額の代わりに「5時間枠と週間枠がある」「モデル別の倍率がある」「枠を超えるとクレジットで続く」といった条件を書きます。

並べたうえで、判断の文を一行足します。たとえば「月120回・出力800トークンの使い方なら、従量の試算は月 $1.92（税別）。月 $20 のプランは枠の余裕と上位モデルの利用に価値があるかで判断する」となります。金額の大小ではなく、何に払っているかの違いとして書きます。

試算シートの形

成果物の列は次のとおりです。

列書くこと
用途何のための利用か
モデル表示名と[[model-id
1か月の回数前の記事で数えた値
入力トークン／回おおよその値
出力トークン／回おおよその値
入力単価・出力単価額・単位・通貨・税・確認日
適用した条件段階、バッチ、キャッシュ、地域
試算額税別の合計
前提と未確認のこと反映しなかった条件

最後の列が、このシートの要です。ここが空の試算は、条件を落としています。

金額の欄で「$0.00」と書けるのは、公式に 0 と示されている場合だけです。判定用のモデルの中には料金表で無料と示されているものがありますが、それは 0 と書けます。一方、単価が確認できなかった場合は 0 ではなく「未確認」と書きます。この二つを同じ扱いにすると、無料だと思って使ったら課金されていた、という事故になります。

試す人向け演習・記入例と確認の観点

演習：候補を一つだけ試算する

前の記事のメモと、前章の選定表を使います。新しい契約も、API キーも要りません。公開されている単価だけで計算できます。

  1. 選定表から、試算する候補を一つ選びます。最初から全部やると疲れます。
  2. そのモデルの入力単価と出力単価を、公式の料金表で探します。100万トークンあたりかどうか、税別かどうかを確かめます。
  3. 1か月の回数、入力トークン、出力トークンを、前の記事のメモから写します。
  4. 入力の費用と出力の費用を別々に計算し、足します。
  5. 適用できる条件を探します。1回の入力が段階の境目を超えているか、急がない処理が何割か、同じ前置きを送っているか。
  6. 反映しなかった条件を「前提と未確認のこと」に書きます。確認日も入れます。

期待する結果は、試算額が一つ出て、その下に三つ以上の前提が並んでいる状態です。前提が三つ未満なら、条件を見落としています。

うまくいかないときは、次のどれかです。単価が2つあってどちらを使うか分からない場合は、1回の入力の長さで段階を選びます。合計額では選びません。計算が合わない場合は、トークン数を100万で割り忘れているか、入力と出力を逆にしています。桁が大きくずれるのは、たいていこの二つです。モデルの単価が見つからない場合は、API で提供されていない可能性があります。画面でしか使えないモデルは単価を持たないので、そのときは試算の対象から外し、「API未提供」と書きます。

できあがるもの

成果物は、上の九列を持つ一行のシートと、その下の三行の注記です。

一行の例を挙げます。用途は議事録の下書き、モデルは Claude Sonnet 5.5、月120回、入力4,000トークン、出力800トークン。試算は $1.92（税別）。

注記は次の三行です。

  • バッチ割引は未適用（急がない処理が4割あるが、まとめて流す仕組みは未整備）
  • キャッシュは使わない前提（同じ前置きを送っていない）
  • 税別。為替は含まない

この三行があるだけで、この試算は他人に渡せます。数字は条件が変われば変わりますが、前提が書いてあれば、どこを直せばよいかが分かるからです。

このサイトのAI図鑑の比較ページでは、モデルごとの単価と確認日を並べて見られます。単価の取り違えを防ぐ下読みに使ってください。

評価

シートは、次の三つで点検します。第一に、入力と出力が別の行または別の列になっているか。第二に、各単価に通貨・税・単位・確認日が付いているか。第三に、前提と未確認のことが三つ以上書かれているかです。

もう一つ、確かめ方があります。シートを別の人に渡して、同じ数を入れてもらってください。同じ答えが出れば、計算式と前提が正しく伝わっています。違う答えが出たら、どこかが暗黙の前提になっています。多くの場合、それはトークン数の見積もりか、段階の選び方です。

逆に、次の状態なら書き直しが必要です。合計だけが書いてあって内訳が無い。単価の確認日が入っていない。月額プランと同じ列に金額が並んでいる。どれも、条件を落とした印です。

ここまでで、製品を層で見る方法、モデルを名前で選ぶ方法、費用を試算する方法が揃いました。次は、この三つを使って実際に手を動かす段階に入ります。第26章以降で、デスクトップでの活用、CLI、ハーネスの比較を順に扱う予定です。公開までは、図鑑のモデル一覧で候補を引きながら、ここまでのシートを埋めておいてください。
