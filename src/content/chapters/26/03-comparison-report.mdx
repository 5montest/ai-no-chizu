前の二つの記事で、条件表と許可表を作りました。この記事では、その二つを持って、実際に同じ資料を二つの入口で試し、結果を一枚のレポートにまとめます。目的は、優劣を決めることではありません。自分の作業で、どちらが何をしてくれて、何をしてくれないかを、あとから読み返せる形で残すことです。

この記事の記述は、2026-10-28 に公式ページで確認した内容にもとづきます。比較の手順そのものは、このサイトの作成環境では実行していません。**未実機確認**です。手順をなぞって、自分の結果を自分の言葉で書いてください。

## 条件をそろえないと、違いは見えない

比較でいちばん多い失敗は、条件をそろえずに結果だけを並べることです。昨日ブラウザ版で試した資料を、今日はアプリでもう少し大きい資料で試す。返ってきた答えが違っても、道具の違いなのか資料の違いなのかは分かりません。

そろえるものは三つです。

- **資料**。同じファイルを、同じ場所から渡します。PDF なら同じページ数、表計算なら同じシート。片方だけ先に編集しない。
- **質問**。同じ文面で聞きます。「要約してください」ではなく、「この規程のうち、経費の上限に関する記述を、該当する節番号つきで三つ挙げてください」のように、答えの形まで指定します。曖昧な質問は、道具の違いより揺れの違いを測ってしまいます。
- **時間**。同じ長さで試します。待ち時間を測るなら、測り始めと測り終わりの位置を決めておきます。

資料は、三種類あると違いが出ます。文字だけの文書、表を含む文書、そして少し古い言い回しの混ざった文書です。文字だけなら差が出にくく、表と古い言い回しで差が出ます。第三者の著作物や個人情報は使わず、自分で書いたか、社内で使ってよいと確認した資料にしてください。

## データの扱いは、確認できた範囲で書く

道具を選ぶとき、もう一つ気になるのが、渡した資料がどう扱われるかです。ここは、確認できた範囲と、できなかった範囲を分けて書きます。

**Anthropic のプライバシーポリシー**には、次のように書かれています。ポリシーは、自社のウェブサイト、Claude.ai、その他の Anthropic の製品とサービスの利用に適用される。ただし、事業向けの提供で顧客に代わって処理する内容には適用されず、Enterprise アカウントのような場合は顧客との契約が定める。学習の材料には、サービスの入力と出力も含まれる（利用者がオプトアウトしない場合）。入力と出力は、アカウントの設定からオプトアウトしない限り、モデルの訓練と改善に使うことがある。オプトアウトしたあとも、会話が安全性の確認のために印を付けられた場合や、利用者が明示的に報告した場合は、モデルの改善に使うことがある。削除すると、会話履歴からはすぐに消え、バックエンドからは 30 日以内に自動で削除される。[[data-retention|保存期間]]は、合理的に必要な期間とされ、固定の日数は示されていない。

**OpenAI の [[api|API]] のデータの説明**には、次のように書かれています。API に送ったデータは、明示的にオプトインしない限り、モデルの訓練や改善には使わない。不正利用の記録は最大 30 日保持する。ゼロ保持（ZDR）は申請して承認されると有効になり、その状態では保存の指定は常に無効として扱われる。一部のエンドポイントは、アプリケーションの状態を 30 日保持する。このページは API の利用について書かれたもので、ChatGPT の一般利用者の扱いを述べたものではありません。

そして、**確認できなかったこと**。ChatGPT の一般利用者向けのポリシーページと、デスクトップアプリのヘルプ記事は、2026-10-28 の取得時に 403 を返しました。したがって、この記事では ChatGPT 側の学習利用の有無も、保持期間も書きません。推測で埋めると、読者が自分の契約と混同します。

代わりに、自分のアカウントの設定画面で確かめてください。データの学習利用に関する設定、会話の保持に関する設定、デスクトップアプリから渡したファイルの扱い。見つけた設定の名前と、確認した日付を記録に残します。設定画面で見たものは、それも一次資料です。

## レポートは、七つの列で書く

結果は、次の形で一枚にまとめます。行が入口、列が観点です。

| 列 | 書くこと |
| --- | --- |
| 入口 | ブラウザ版か、デスクトップアプリか。版と確認日 |
| できたこと | 頼んだ作業のうち、期待どおりに終わったもの |
| できなかったこと | 失敗したもの。断られたもの。途中で止まったもの |
| 出た許可 | 何を許可として求められたか。許可したか、断ったか |
| データの扱い | 公式に確認できた記述と、確認できなかった項目 |
| 手間 | 準備にかかった時間、待ち時間、やり直した回数 |
| 未確認 | 自分の環境では確かめられなかったこと |

「できなかったこと」の列を空にしないでください。空になるのは、たいてい作業が簡単すぎたときです。表の読ませ方、古い言い回しの解釈、ファイルの書き込み。難しい側の仕事を一つ入れておくと、違いが出ます。

「手間」の列は、数字で書きます。主観で「速かった」と書いても、次に比べられません。準備に何分、最初の応答まで何秒、やり直しが何回。ストップウォッチで測る必要はなく、時計を見て書けば足ります。

## 差が出たところを、三つだけ拾う

全部の行を比べると、たいてい差が出ます。大事なのは、差が出た理由を一つずつ説明することです。説明できない差は、次に同じ結果が出るかどうか分かりません。

理由の候補は、四つに分かれます。

- **入口の違い**。フォルダを直接読めるか、アップロードが要るか。これは前の記事で扱った範囲の違いです。
- **許可の違い**。読み取りだけか、書き込みもできるか。サンドボックスの設定で変わります。
- **資料の渡し方の違い**。PDF のまま渡したか、テキストにして渡したか。画像の解像度が足りていたか。
- **質問の書き方の違い**。答えの形を指定したか、指定しなかったか。

一つ目と二つ目は道具の違いですが、三つ目と四つ目は自分の側の違いです。自分の側の違いを道具の違いと書いてしまうと、レポートが「このアプリは表が読めない」で終わります。実際は、解像度が足りなかっただけかもしれません。

## 演習：一枚のレポートを仕上げる

二つの入口のうち、片方だけしか使えない場合も、この演習は成立します。その場合は、一つの入口について、同じ列を埋めてください。

1. 資料を三つ用意する。文字だけ、表を含む、古い言い回しを含む。すべて自分で用意したものにする。
2. 質問を三つ書く。それぞれ、答えの形を指定する。
3. 条件表と許可表を、レポートの上に置く。何を許可した状態で試したかを、結果より先に書く。
4. 片方の入口で、3資料 × 3質問を順に試す。各回について、七つの列を埋める。
5. もう片方の入口で、同じ順序で試す。資料も質問も変えない。
6. 差が出た箇所を三つ選び、四つの理由のどれかを当てはめる。当てはまらないなら「理由不明」と書く。
7. 最後に「次に確かめること」を三行で書く。未確認の欄から選ぶ。

手順 6 が要点です。「理由不明」と書く欄があると、レポートは正直になります。分からないことを分かったふりで埋めた時点で、この記録は次に使えません。

## うまくいかないときの見方

結果が安定しないときは、質問の広さを疑います。「この資料について教えてください」では、毎回違う答えが返って当然です。答えの形（箇条書き、節番号つき、三つだけ）を指定すると、比べられる形になります。

表が崩れるときは、渡し方を変えます。表を画像として渡すより、テキストや表計算のまま渡すほうが構造は保たれます。逆に、レイアウトそのものを見たいなら画像のまま渡します。どちらが良かったかを、レポートの「資料の渡し方」に書きます。

待ち時間が測れないときは、測る位置を固定します。依頼を送った時刻と、最初の文字が出た時刻。ここを決めておかないと、あとから比べられません。

データの扱いが分からないときは、設定画面を見ます。見つからない場合は、その旨を「未確認」に書き、確認した日付を添えます。取れなかったページの URL も残しておくと、次に確認するときに探し直さずに済みます。

## 評価

五つの観点で点検します。資料と質問をそろえたか。許可した範囲を、結果より先に書いたか。できなかったことを、空欄にせず書いたか。差が出た理由を、四つの候補から選んで説明したか。そして、確認できなかった項目に日付つきの「未確認」を残したか。

書き直しが要るのは、次の状態です。条件を変えたまま結果だけを並べた。できなかった欄が空のまま。データの扱いを、確認していないのに断定した。理由の列が、すべて「使いにくい」で埋まっている。どれも、次に同じ判断ができない記録です。

## できあがるもの

手元に残るのは、条件表、許可表、比較レポート一枚、そして次に確かめることの一覧です。この四つがあれば、別の製品が出てきたときも、同じ順番で試せます。条件を書き、許可を決め、同じ資料で試し、違いの理由を書く。道具が変わっても、この順番は変わりません。

製品とモデルの位置づけは、[AI図鑑](/zukan/)で名前から引けます。値には確認日が付いているので、この記事の日付と見比べてください。図鑑の値と自分のレポートが食い違ったら、確認日を比べて、新しいほうを採ります。
