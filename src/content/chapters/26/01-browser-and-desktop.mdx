前の章では、料金の読み方と、ターミナルから使う道具を扱いました。この章では、いちばん多くの人が最初に使うブラウザのタブとデスクトップアプリを並べます。

同じアカウントで、同じモデルに、同じ質問をする。それでもブラウザ版とデスクトップアプリでは、できることが変わります。変わるのはモデルの賢さではなく、モデルの前に置かれるクライアントと、そのクライアントに許す範囲です。

この記事の記述は2026-10-28 に各社の公式ページで確認した内容にもとづきます。このサイトの作成環境では、どちらのアプリも導入していません。つまり**未実機確認**です。画面の文言や手順の細部は、あなたの環境と一致しないことがあります。

## 変わるのはモデルではなく、モデルの前後

最初に層をそろえます。ブラウザ版もデスクトップアプリも、同じモデルを呼び出すためのアプリです。これらは[[harness]]の一種で、モデルそのものではありません。五層の分け方は[第23章](/chapters/23/01-five-layers/)で扱いました。

使うアプリが変わると、三つの点が変わります。一つは**触れる範囲**。ブラウザのタブは、アップロードしたファイルと、開いているページしか見ません。デスクトップアプリは、指定したフォルダをそのまま読めます。二つは**OS との結びつき**。画面を見る、声で入力する、ほかのアプリとつなぐ、といった機能は、OS の上で動くアプリでないと実現しません。三つは**更新の経路**。ブラウザは開くたびに新しいバージョンが届きますが、アプリは導入した方法によって更新のされ方が変わります。

この三つはどれも「便利になった」と一言では言えません。触れる範囲が広がることは、読まれて困るファイルが増えることでもあります。OS と結びつくことは、許可をどこまで出すかを決める必要が出ることでもあります。更新の経路は、業務でアプリを配るときに重要になります。

## Claude のデスクトップアプリは、対応範囲が公式に書かれている

Claude のデスクトップアプリは、公式のサポート記事に対応範囲が細かく書かれています。まず、動く環境です。

| 項目 | 公式の記載 |
| --- | --- |
| macOS | 13（Ventura）以降 |
| Windows | 10 以降 |
| Linux | Ubuntu 22.04 LTS 以降、または Debian 12（bookworm）以降。x64 か arm64 |

次に、プランごとに使える機能です。記事には表があり、Chat は Free・Pro・Max・Team・Enterprise のすべて、Claude Code は Pro・Max・Team・Enterprise、Cowork は有料プラン（Pro・Max・Team・Enterprise）のすべてで使えると書かれています。同じアプリを入れても、契約によって使える機能が違う、という形です。

導入はダウンロードページからファイルを落として開き、アプリケーションフォルダかスタートメニューから起動し、アカウントでサインインします。Linux だけ道が二つあり、リポジトリを追加して `apt` で入れる方法と、`.deb` を直接入れる方法です。リポジトリを追加する手順では、鍵のファイルを `/etc/apt/keyrings` に置き、`sources.list.d` に署名付きの取得元を書いてから、`apt update` と `apt install` を実行すると説明されています。

## ChatGPT のデスクトップアプリは、書かれていない欄がある

ChatGPT のデスクトップアプリは、公式ドキュメントのアプリのページで確認できます。書かれているのは次の四つです。

- macOS・Windows・Linux 向けにダウンロードできること。
- ChatGPT アカウントでサインインして使うこと。
- チャットを始めるか、プロジェクトを作るか、フォルダを開いて始められること。開いた場所のファイルと文脈を ChatGPT が使えること。
- 作業の中で ChatGPT と Codex のどちらを使うかを選べること。ブラウザと自分のコンピュータを使う機能、タスクに必要な道具へのアクセスに触れていること。

書かれていないことも同じだけ大事です。この記事の確認時点では、対応する OS のバージョン、プランによる機能の違い、許可をどう求めるかの説明、音声入力の有無は、このページには見つかりませんでした。ヘルプセンターの該当記事と、一般利用者向けのポリシーページは、取得を試みた時点で 403 を返しました。

だから、この記事では ChatGPT 側の対応バージョンやプランの条件を書きません。分からないものを「たぶんこうだろう」で埋めると、あとで同じ表を作り直せなくなります。代わりに、自分の環境で確かめた結果と、確かめた日付を記録に残してください。

## 更新のされ方が、配布の設計を決める

Claude の Linux 版には、はっきりした但し書きがあります。アプリは自分自身を更新しない、更新はシステムの通常のパッケージ更新として届く、と書かれています。そして、`.deb` をダウンロードしただけでは、通常のパッケージ更新の対象にはならないとも書かれています。

これは小さな違いに見えて、業務では重要です。同じ「Claude のデスクトップアプリを入れた」でも、リポジトリを追加した人と `.deb` を落とした人では、半年後のバージョンが違います。何が入っているかを把握したいなら、配布方法を決めた時点で、更新の経路も一緒に決めておく必要があります。

macOS と Windows の更新の扱いは、この記事で参照した範囲では確認できませんでした。未確認として扱ってください。

## 選ぶ前に、条件を一枚に書く

二つを比べる前に、自分の条件を表にします。ここが空欄のままだと、あとで「思っていたのと違う」が起きます。

| 項目 | 書くこと |
| --- | --- |
| 環境 | OS とバージョン、[[cpu\|CPU]] の種類（x64 か arm64） |
| 契約 | 使っているプラン名。無料版か有料版か |
| 導入方法 | 配布ページから入れたか、パッケージ管理で入れたか |
| 更新の経路 | 自動で更新されるか、自分で入れ直すか |
| 読ませるフォルダ | どのディレクトリを許可するか。仕事の資料と私用の資料を分ける |
| 使いたい機能 | フォルダを読む、画面を見る、声で入力する、ほかのアプリとつなぐ |
| 確認日と出典 | どのページの、いつの記述か |

使いたい機能の欄は思いついた順に書いて構いません。書いたあとで、公式の対応表と突き合わせます。Claude なら上の表と、Linux の制限の一覧です。ChatGPT なら、公式ページに書かれていることだけを根拠にします。

## 演習：導入の前に、条件表を埋める

アプリは入れなくても構いません。表を埋めることが演習です。入れる場合は、自分の環境で、自分の責任の範囲で行ってください。職場の端末なら、先に管理者に確認します。

1. 自分の OS とバージョンを書く。macOS なら「システム設定」の「一般」→「情報」、Windows なら「設定」→「システム」→「バージョン情報」、Linux なら `/etc/os-release` を見ます。
2. 公式ページで、そのバージョンが対応範囲に入っているか確かめる。入っていなければ、そこで止まります。
3. 契約しているプランを書く。無料版か有料版か、チームの契約か個人の契約か。
4. 使いたい機能を三つ書く。たとえば「資料のフォルダを読ませる」「画面を見せる」「声で入力する」。
5. 三つのそれぞれについて、公式ページに対応の記載があるかを調べる。書いていなければ「未確認」と書き、確認先の URL と日付を添える。
6. 更新の経路を書く。自動か、手動か、配布元はどこか。

期待する結果は、表の欄が「確認済み」と「未確認」に分かれることです。全部埋まる必要はありません。埋まらなかった欄に日付つきの「未確認」が入っていることが、この演習の成果です。

## うまくいかないときの見方

対応していない OS のバージョンを使っていると、導入の途中で止まります。Claude の macOS は 13 以降、Windows は 10 以降と明記されています。古い版を使い続ける必要があるなら、ブラウザ版を使います。

入れているのに機能が足りないときは、プランを先に見ます。同じアプリでも、Cowork は有料プラン、Claude Code は Pro 以上と書かれています。アプリの不具合を疑う前に、契約の欄を確かめてください。

Linux で入れたバージョンが古いままなら、更新の経路を疑います。`.deb` を落としただけでは、システムの更新に載りません。リポジトリを追加したかどうかで、その後の届き方が変わります。

公式ページに条件が見つからないときは、探し方を変えます。この記事の確認時点では、ChatGPT のヘルプセンターとポリシーの一部が 403 を返しました。取れないときは、取れなかった事実と日付を記録に残し、アプリの設定画面で自分の目で確かめます。設定画面で見た内容も、確認日つきの記録になります。

## 評価

五つの観点で点検します。OS とバージョンを書いたか。契約しているプランを書いたか。使いたい機能のそれぞれに、公式の記載があるかを確かめたか。更新の経路を書いたか。そして、確認できなかった欄に「未確認」と日付を添えたか。

書き直しが要るのは、次の状態です。OS のバージョンを書かずに「入った」とだけ記録した。使いたい機能を、公式の対応表と突き合わせていない。確認できなかった欄を、自分の推測で埋めた。どれも、あとで同じ判断ができない記録です。

## できあがるもの

手元に残るのは、条件表一枚と、確認できたこと・できなかったことの一覧です。この表があると、次に別の利用方法を試すときも、同じ順番で比べられます。

次の記事では、この表の「読ませるフォルダ」と「使いたい機能」を、許可の一覧に変えます。どこまで読ませ、どこまで書かせ、通信をどう扱うか。[ファイル・画面・音声をどこまで許すか](/chapters/26/02-permissions/)へ進んでください。
