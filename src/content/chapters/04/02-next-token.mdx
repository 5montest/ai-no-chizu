LLMの説明でよく使われる「次の単語を予測しているだけ」という表現は、半分は正確で、半分は誤解を招きます。確かにモデルの基本的な出力は次のトークンの分布です。しかし、その分布から一つを選ぶ過程には、温度やTop-pといった設定があり、選ばれた結果が次の入力になります。この連鎖が、単なる単語当て以上の振る舞いを生みます。

## モデルが出すのは確率の表

「今日の天気は」という入力の続きを考えます。モデルは語彙中の全トークンについてスコア、[[logits|ロジット]]を出し、Softmaxで確率に変換します。たとえば「晴れ」が0.62、「雨」が0.21、「全国」が0.10、残りの語彙全体で0.07、といった具合です。

確率の合計は1になります。モデルが返すのは、この分布と、そこから選ばれた一つのトークンです。文章全体を一括で生成しているわけではありません。

| 候補 | ロジット | 確率（例） |
| --- | --- | --- |
| 晴れ | 3.2 | 0.62 |
| 雨 | 2.1 | 0.21 |
| 全国 | 1.4 | 0.10 |
| その他（残りの語彙すべて） | — | 0.07 |

確率は `exp(z) / Σexp(z)` で計算します。exp(3.2)≒24.5、exp(2.1)≒8.2、exp(1.4)≒4.1 で、語彙全体の合計が約39.5なら、上の確率になります。「その他」は残りの数千から数万のトークンをまとめた行で、個々のロジットを並べる代わりに合計だけを示しています。

数値は説明のための例です。実際の値はモデル・文脈・語彙によって変わります。

## 候補の選び方を変える

確率分布から一つを選ぶ方法は、大きく三つに分けられます。

- Greedy：毎回、最も確率の高いトークンを選ぶ。再現性は高いが、同じ言い回しに陥りやすい。
- Temperature：分布の尖り具合を調整する。低いほど同じ候補に寄り、高いほどばらつきが増える。
- Top-p / Top-k：候補の範囲を制限してから選ぶ。低確率の突飛なトークンを避けつつ、多様性を残す。

[[temperature|Temperature]]は「創造性のつまみ」と説明されることがありますが、正確には**分布の形を変えるパラメータ**です。ロジットを温度で割ってからSoftmaxにかけるため、温度を上げると分布は平らになり、普段は選ばれない候補が選ばれる機会が増えます。温度を下げると分布は尖り、最上位の候補に集中します。

温度を下げると「安全側」になると説明されることがありますが、これは一つの軸だけを見た言い方です。少なくとも次の四つは、別のものとして考える必要があります。

| 軸 | 温度との関係 |
| --- | --- |
| ばらつき | 温度が低いほど、同じ入力に対する出力の違いが小さくなる。 |
| 再現性 | 温度を0に近づけると上がる。ただし並列計算や実装の変更により、完全な一致は保証されない。 |
| 安全性 | 有害な出力や指示違反の起きにくさ。学習時の調整、システム指示、入出力のフィルタが主で、温度を下げれば解決するものではない。 |
| 事実の正確さ | 温度を下げても上がるとは限らない。同じ誤りを、安定して繰り返すことがある。 |

[[top-p|Top-p]]は、確率の高い順に候補を足していき、累積がpに達するまでの集合から選びます。p=0.9なら、上位候補だけで確率の90%をカバーする集合です。候補の数は分布によって変わります。

<Callout type="myth">
「Temperatureを上げるとモデルが賢くなる」「下げれば必ず正確になる」は、どちらも言い過ぎです。温度は知能や知識を変えず、選び方だけを変えます。事実誤認の原因は、知識の欠如、文脈の不足、学習データの偏りなど多岐にわたり、サンプリング設定だけで解決できるものではありません。
</Callout>

## 同じ質問で答えが変わる理由

チャットAIに同じ質問をしたのに、毎回少しずつ表現が違う。これは、確率分布から確率的に選んでいるからです。特に温度が0より大きい場合、同じ入力でも選ばれるトークンが変わり、その後の文脈も変わります。

再現性が必要な場面では、温度を0に近づける、シードを固定する、といった設定が用意されていることがあります。ただし、モデルのバージョン更新、並列計算の非決定性、提供元の実装変更によって、完全な再現は保証されません。同じ結果を得ることは、同じ品質を得ることとは別です。

## 流暢さと正しさは別の軸

次トークン予測は学習データに現れるパターンを再現する仕組みです。文法的に自然で、文脈に合った続きを作るのは得意です。しかし、その文が事実かどうかを判定する機能は、基本的には持っていません。[[hallucination|ハルシネーション]]が起こるのは、この構造的な理由によります。

だからこそ、事実が必要な場面では検索、データベース、引用、人の確認を組み合わせます。モデルの出力を「候補」として扱い、**どこで検証するか**を設計することが、実務では重要になります。

<DeepDive title="なぜ「それらしい」文章が作れるのか">
  大規模な学習データには、人間の文章の統計的なパターンが含まれています。語の並び、言い回し、説明の型、質問への答え方。次トークン予測を大規模に学習すると、これらのパターンがパラメータに圧縮されます。

  その結果、初めて見る質問に対しても、学習したパターンの組み合わせとして答えを生成できます。これを「理解している」と呼ぶかどうかは立場が分かれますが、少なくとも、入力の意味を辞書で引いて組み立てているわけではないことは確かです。パターンの一般化と、事実の保証は、別の問題として考える必要があります。
</DeepDive>
