# 読者像別レビューと改修（2026-10-30）

対象：AIの地図の全315ページ（章コンテンツ94・章入口32・用語辞典122・AI図鑑59・その他8）。
目的：想定読者から見て「字ばかりで見にくい」箇所を洗い出し、見た目と内容の両方を改善する。

## 想定読者（今回の基準）

1. 生成AIを業務で使い始めた社会人（非エンジニア）
2. AI関連の提案を読む立場の人
3. 社内導入の判断に関わる人
4. 仕組みから学び直したい人
5. モデルや製品を比較して選びたい人
6. CLIエージェントで実装したい人

前提：基礎編はプログラミングの知識がなくても読める。実践編の一部の章はターミナルとGitの操作を前提にする。

## 方法

- 公開と同じ設定でビルドし、全315ページを Chromium で撮影（desktop 1280×900 / mobile 390×844、full page）。
- DOMからページ密度を計測（本文文字数、画面数、図・表・コールアウト・detailsの数、連続する段落数、最長段落、横スクロールの有無、画像のaltと読み込み）。
- 読者像を分担した4名のレビュアーが、スクリーンショット・メトリクス・MDX/コンポーネントのソースを突き合わせて指摘（112件：P0 2 / P1 29 / P2 59 / P3 22）。
- 修正は3名＋編集の分担で実施し、ビルド・検証スクリプト・再撮影で確認した。

## 見つかった主な問題

| 分類 | 事実 | 影響 |
| --- | --- | --- |
| 行長と文字サイズ | 本文は1行約52字（`--measure: 54em`・16px・行間1.95）。日本語の長文としては1行が長く、段落の切れ目も見えにくい | 長いページで行を見失う。業務読者ほど読み進めにくい |
| 見出し階層 | 本文を18pxに上げた結果、h3=17px・h4=15px、ページ要約15pxが本文より小さくなった | 節の切れ目と「何のページか」の材料が本文に埋もれる |
| 図の比率 | 94ページ中81ページが図1枚のみ。実践編後半は1画面あたりの本文が基礎編の約1.6倍（759字 vs 462字） | 長いページほど「文字の壁」になる |
| ページの長さ | 最長は 28/03（desktop 15.9画面・mobile 27画面）。mobileで8画面超が75ページ | スマートフォンで読み切れず、位置も失う |
| モバイルの表 | 390px幅で3列表が1行6〜7字になり、語中で折り返す（横スクロールも案内なし） | 料金・上限・比較の確認という主要な目的を果たせない |
| 前提と現在地 | ターミナル/Git 前提が画面上に出ておらず、長いページで現在地が分からない | 「自分の環境では読めない」ことに後から気づく |
| 「提案を読む」入口 | about と検索データは読者像として名乗るが、学習ルートに該当がなく、中心教材の第22章もルート外 | 提案を評価したい読者が入口を見つけられない |
| 正確さ | 25/01 に「図鑑では席単価が未確認」という事実誤り、および文字数→トークン換算の矛盾（1文字1トークン／÷4／÷1.5） | 費用の稟議資料に使うと見積もりを誤る |
| リファレンス | 比較ページに金額がなく、図鑑カードの説明が料金・仕様の断片。検索索引に図鑑57件が入っていない | 「比較して選びたい」読者の中心動線が成立しない |
| 図・コードの描画 | Mermaid図が本文幅に縮小されてラベルが約8px。コードブロックは枠もコピーもなく本文と同化 | 仕組みを学ぶ読者・CLIで実装する読者の価値が下がる |

## 実装した改善

### 1. 読みやすさ（タイポグラフィ）

- 本文：`--measure` 54em → 44em（1行約44字）、本文 16px → 18px（1.125rem）、行間 1.95 → 1.85、段落間隔 1.15em。
- 見出し：h2 1.55rem / h3 1.25rem / h4 1.0625rem（本文より必ず大）。
- 導入文・章の問い・要点リスト・表・一覧・aboutカードの文字サイズを一段上げ、ページ種別間の読み味の差を縮めた。
- 記事冒頭に「この章のゴール」を追加（frontmatterを増やさず curriculum の outcome を表示）。全32章に outcome を整備。

### 2. 現在地と読み進め（ナビゲーション）

- 記事上部に読書の進捗線、モバイルは読み進めると現れる固定「目次」ボタン＋ダイアログ。
- 章一覧に部のジャンプチップ、記事のメタ行に「前提」（前章リンク・ターミナルとGit）。
- 6本目の学習ルート「AIの提案を読む立場の方」を追加（22/02 → 22/01 → 18/02 → 18/04 → 25/01）。第22章の題を「発表と評価の読み方」に変更。
- ヒーローに想定読者の1行、ルートカードを3列×2行に整理しCTA位置をそろえた。`/start/` の記事一覧はモバイルで折りたたみ。

### 3. 図・表・コード

- 表：ビルド時に `table-wrap` で包み、760px以下は最小幅＋横スクロール＋「横にスクロールできます」の案内。
- 図：Mermaidの縮小を原寸の82%までに緩め、はみ出す分は枠内スクロール（デスクトップ）。スマートフォンは全体表示を優先し、拡大ビューアーで読む。
- コード：`pre` の枠・余白・横スクロール、言語名とコピーボタン、ダークテーマの配色切替を追加。
- 工程・比較カード図を3ページ追加（31/01, 29/01, 28/04）。28/03 は冒頭に読み方と早見表、製品カードは折りたたみへ。

### 4. 業務読者向けの内容

- 25/01 の事実誤りを修正し、トークン換算の記述を 05/01・25/02・32/03 で統一（概算であることも明記）。
- 21/02 に「契約書とSLAで確認する項目」（SLA・免責・解約・価格改定・再委託・データ所在地）。
- 25/02 に「席単価の積み上げ（法人プラン）」の記入例（架空・税/為替/日付の注記つき）。
- 22/02・18/04・25/01・25/02 に「提案書・見積書・稟議」の文脈を追加。18/01・18/02 に用語リンクと導線。
- 確認シートに第7グループ「提案書・見積書を読む」6項目を追加（6群18項目 → 7群24項目）。ダウンロード用テンプレートも同期。
- クイズの誤答9問を実務で出会う誤りに差し替え、22/03 の頻度断定を緩和。20/02・21/01 に「このページのまとめ」を追加。

### 5. リファレンス（AI図鑑・用語辞典・クイズ）

- 比較ページに金額4行（月額／従量入力／従量出力／用途別従量）を追加し、各セルに単位・税・取得日・公式/再販を併記。行見出しはsticky。
- 図鑑57件に `summary`、うち12件に `description` を追加し、一覧カードと「これは何か」を製品説明に変更。出典メモは「記録メモ」へ移動。
- 比較の空状態にプリセット、選択件数の表示を一本化、6件上限の説明を操作位置へ、絞り込み状態のURL反映。
- 用語一覧に読みと「あ行／か行／英字」の行見出し、用語詳細に前後ナビと誤解のコールアウト。
- クイズの解説に復習リンク、初期画面に全問数と章別内訳、再挑戦は再抽選。404に検索・図鑑・学習ルートへの導線。
- サイト内検索の索引にAI図鑑57件と静的4ページを追加（結果に「製品」ラベル）。

### 6. 保守性・開発環境

- Windows（CRLF）でも `remark-guide-links` のfrontmatter解析が通るよう修正し、`.gitattributes` で改行をLFに統一。
- `scripts/validate-content.mjs` の Windows 絶対パス import を `pathToFileURL` で修正。
- 非推奨の `markdown.remarkPlugins` を `unified()` に移行し、ビルド警告を解消。

## PR取り込み前の追加確認

PR #1の変更を、本文の読みやすさ、情報を省いたときの正確さ、料金の単位、操作と表示の観点で再確認した。本文サイズ、6本の学習ルート、目次、表・コードの操作、辞典の索引、クイズの復習導線は採用した。

- 法人プランの比較に「1席あたり」を付け、確認済みの選択肢と未確認の額を分けた。専用モデルの料金を先頭2件で省略せず、音声単価も表示する。トークン単価の入力長などの条件も残した。
- 製品の要約を表示しても元の確認メモを読めるようにした。説明文に複製されていた単価は料金欄へ集約し、公式名との対応が未確定な再販名はその状態を要約にも残した。

- 検索にAPIモデルIDを含め、章番号のないページには空の「第章」を表示しない。
- 文字数からトークン数への換算は、概算の仮定と実測を分けた。履歴が常に全量送られるという断定と、古いChatGPT料金の未掲載説明も訂正。PowerShellの準備にはGit初期化を明記した。
