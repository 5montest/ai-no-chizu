## 事実と説明の修正

| 記述 | 反映内容 |
| --- | --- |
| 温度を0へ近づければ、回答が決定的になる | 有力な候補が選ばれやすくなることと、回答の完全一致が保証されないことを分けた。クイズ解説も修正。 |
| 規則が数百を超えると保守できなくなる | 根拠のない件数の閾値を削り、規則間の依存関係が複雑になると保守が難しいと説明。 |
| ベクトル検索なら数百万件から短時間で返る | 索引、機器、件数、検索精度によって変わると説明。 |
| 生成が逐次的だから出力単価が高い | 計算の特徴と事業者の値付けの理由を分離。料金表で入力・出力を別々に確認する説明へ変更。 |
| ローカル実行なら情報が外に出ず、完全に再現できると読める | 配置と重みを選べる利点を残し、外部ツールやログの送信先、実行環境も確認すると補足。 |
| 評価用の数十件、20〜50件で十分と読める | 初期検証の目安であることを明記。用途と誤りの影響に応じて件数を決める。 |

| 「学習に使わない」と「保存しない」が混同されやすい | 独立した確認項目として本文・図・シートに反映。OpenAIのAPI資料を具体例として追加。 |

## 図の内容と実装

生成した図は次の6点。

1. 提供元・モデル・アプリの違い
2. 資料の受け渡し・RAG・追加学習
3. エージェントの作業と実行権限
4. LLMが文章を作る流れ
5. 問い合わせ対応で任せる範囲
6. 入力情報の行き先と利用条件

配信用WebPは1点約100〜180KB、6点合計約0.8MB。拡大リンク、代替テキスト、同じ内容を文章で読む表示を備える。画像内の文字に説明を閉じ込めず、本文と合わせて確認できる。

生成方法は組み込みの `image_gen`。元のPNGと全プロンプトは `output/imagegen/`、配信用ファイルは既存サイトの `public/images/guide/` に保存した。既存サイトの `docs/visual-assets-2026-10-28.md` に生成プロンプトと公式アイコンの出典を記録した。

Mermaidの新しい10図は、AI史、入出力のモダリティ、音声処理、配置、発表の読み方、費用、CLI検収、ハーネス比較、拡張の役割、音声パイプラインを説明する。
