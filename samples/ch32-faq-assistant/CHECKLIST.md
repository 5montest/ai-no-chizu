# 公開前チェックリスト

このチェックリストは、第32章の「公開前チェック」の実例として、この演習アプリ自身に当てたもの。
各行の状態は、実際にやったことと、やっていないことを分けて書く。確かめていない項目を「済み」とは書かない。

## 代表的な質問で動きを確かめた

CLI で四つの行き先を一通り実行し、画面でも同じ四つを実行した。判定・理由・本文の有無が、CLI と画面で一致した。

| 質問 | 判定 | 画面に出たもの |
| --- | --- | --- |
| 会議室を予約したい | 答える | 本文と出典（設備利用規程 第2条） |
| コピーの紙が詰まった | 答える | 本文と出典（第11条） |
| 給与明細が見たい | 人に回す | 連絡先のみ。本文は出ない |
| 経費の締め切りは？ | 答えない | 連絡先のみ。本文は出ない |

状態：済み（CLI は `node cli.mjs "…"`、画面は Chromium で実行）

## 画面の確認

Chromium 1280×900 と 390×844 で開き、次を確かめた。

- データの読み込みが終わると `body[data-ready="true"]` になる
- 四つの行き先がそれぞれ表示され、色だけでなく文字でも区別できる（バッジに「答える」「人に回す」「答えない」と出る）
- 空の質問では「質問を入力してください。」と出て、判定は走らない
- 候補の一覧は `<details>` で開閉でき、開くと項目名・点数が出る
- Tab キーで入力欄からボタンへ移れる
- 390×844 で横スクロールが出ない（`scrollWidth` と `innerWidth` がどちらも 390）
- コンソールエラー 0件、失敗したリクエスト 0件

状態：済み（Chromium のみ）

## 秘密情報を扱っていないこと

APIキー、トークン、環境変数の読み出しが無い。画面から秘密情報を入力させない。単価を入れる場合も `config.json` に書くのは単価と出典だけで、鍵は置かない。

状態：済み（置いていないことを確認）

## 費用の表示

単価が未入力のため、費用は「未設定」と出る。0円とは表示しない。`cost: null` であることをテストで固定している。

状態：済み。ただし、実際の単価を入れた状態での表示は未確認（実課金を伴うため、この演習では行わない）。

## データとライセンス

FAQ 12件、評価用の質問14件は、この演習のために書いた架空の社内規程。実在の組織の規程ではなく、第三者の文章・画像・音声を含まない。`data/faq.json` の冒頭にもその旨を書いた。

状態：済み

## 未確認として残していること

- **Chromium 以外のブラウザ。** Firefox と Safari では開いていない。`<details>` と `fetch` は広く使われている機能だが、確認したとは書かない。
- **スクリーンリーダーでの読み上げ。** `aria-live="polite"` を付けたが、実際に読み上げさせて確かめてはいない。
- **HTTPS での配信。** 手元の HTTP サーバーでしか開いていない。
- **実際のモデルにつないだ場合の費用と文面。** このアプリはモデルを呼ばない。単価を入れても、出るのは文字数からの概算であって、請求額ではない。
- **長期の運用。** ログの保存、更新の手順、問い合わせの一次受けは、この演習の範囲外。製品として出すなら、この三つを決めてからにする。
