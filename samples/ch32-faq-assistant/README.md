# 設備ヘルプデスク（第32章の演習）

社内FAQ の質問に答える小さな製品を、第32章の題材として作ったもの。外部のAPIもネットワークも使わない。
判定の理屈は `lib/` の中だけにあり、CLI とブラウザ画面は同じ `lib/engine.mjs` を呼ぶ。

## 動かす

```
cd samples/ch32-faq-assistant
node cli.mjs "会議室を予約したい"
node cli.mjs                       # 対話モード。空行か exit で終わる
node --test "test/*.test.mjs"      # 39件
```

ブラウザで見る場合は、このフォルダを HTTP で配信して `index.html` を開く。
この作業フォルダなら <http://192.168.8.10:8090/20261027-website-design-implementation/samples/ch32-faq-assistant/>。
`index.html` をファイルとして直接開くと、モジュールの読み込みと `fetch` が通らないため動かない。

## 何をするか

質問文を語の集合に変え、12件のFAQ項目と突き合わせて順位をつけ、三つの行き先のどれかに振る。

| 行き先 | 条件 | 画面に出るもの |
| --- | --- | --- |
| 答える `answer` | 候補が一つに絞れた | FAQ の本文と出典 |
| 人に回す `escalate` | 機微な語を含む／一位と二位の差が下限未満 | 連絡先だけ。本文は出さない |
| 答えない `refuse` | 語が一つも当たらない／当たりが下限未満 | 連絡先だけ。本文は出さない |

判定に使う値は `config.json` にあり、コードには埋めていない。

```json
{ "retrieval": { "min_coverage": 0.5, "min_margin": 0.15 } }
```

`min_coverage` は「質問の語のうち、一位の項目に当たった割合」の下限、`min_margin` は「一位と二位の点差を一位の点数で割った値」の下限。

## ファイル

```
config.json          判定の下限、費用の単価（未入力）
data/faq.json        架空の社内FAQ 12件
data/eval-questions.json  受け入れ用の質問14件と、期待する判定
lib/text.mjs         正規化と語への分解
lib/retrieval.mjs    索引と順位づけ
lib/routing.mjs      三つの行き先の判定
lib/cost.mjs         トークン数と費用の推定
lib/engine.mjs       上の四つをまとめる
cli.mjs              端末から使う
index.html app.js style.css  ブラウザ画面
test/                node:test の39件
ACCEPTANCE.md        受け入れ条件とテストの対応
CHECKLIST.md         公開前に見る項目
```

## 決めたこと

**本文を出さない判定を先に置いた。** 機微な語（返金、契約、給与、事故など）を含む質問は、候補がどれだけ良くても人に回す。判定の順序は 機微な語 → 当たりゼロ → 当たりの下限 → 点差の下限 → 答える、で固定した。順序を変えると「よく当たったから答えてしまう」経路ができる。

**単価が無ければ費用を出さない。** `config.json` の `unit_price_input_per_1m` と `unit_price_output_per_1m` は空にしてある。空のとき `estimateCost` は `cost: null, priced: false` を返し、画面と CLI は「未設定」と表示する。0円とは書かない。単価を入れるときは `price_source` と `price_checked_at` も一緒に入れる。

**乱数を使わない。** 同じ質問には同じ順位、同じ文面が返る。テストで毎回同じ結果を比べられるようにするため。

## わかっている弱点

- **1文字の語は索引に載らない。** 語は2文字の組で作るので、「鍵」だけでは鍵の項目に当たらない。「会議室の鍵」は会議室の二項目が同点で並び、人に回る（安全側に倒れるが、答えられたはずの質問でもある）。
- **項目の中身が質問に答えているかは見ていない。** 見ているのは「どの項目が近いか」だけ。近い項目の本文が質問に合っていなければ、自信を持って外した答えを返す。`data/eval-questions.json` のような人が書いた質問集で確かめる必要がある。
- **語の重なりしか見ていない。** 「予約を取消したい」と「予約を取り消したい」は同じ語の組にならないため、片方の表記でしか当たらない。
- **トークン数は文字数からの推定。** 1.5文字で1トークンと置いただけの概算で、実際のモデルの分割とは違う。費用の計算もこの推定の上に乗っている。
